# Akiwi.at — Аудит проекта и принятые решения

Дата аудита: 2026-09-18
Проверено: код в репозитории (commit 77f932e), локальная сборка `next build`, живой сайт https://www.akiwi.at (Vercel, hobby-план, проект `akiwi-at`).

---

## 1. Состояние проекта на момент аудита

**Стек:** Next.js 15.5 (App Router), React 19, Tailwind 4 (установлен, почти не используется), деплой на Vercel из GitHub `NSM1276/akiwi.at`.

**Роуты:** `/`, `/search`, `/r/[id]` (87 заведений, SSG), `/chain/[id]` (19 сетей, SSG). Всего 111 статических страниц. Сборка проходит чисто, первый JS ~120 KB.

**Данные:** 87 заведений в `data/venues.js` (адрес, телефон, часы, меню, статус). 19 сетей в `data/chains.js`. Список для главной в `data/data.js` (29 карточек: 19 сетей + 10 одиночных). Расширение для поиска в `data/search-data.js`.

Статусы заведений: verified 53, self 22, unknown 12. У 34 заведений рейтинг-заглушка `4.0` при `reviews: 0`. Ни у одного заведения нет реальных отзывов (`reviews_list` пустой у всех).

**Что в порядке:** сборка, SSG, размер бандла, дизайн-токены, двуязычность DE/EN, объём и качество реальных данных, модель «сеть → филиалы».

## 2. Найденные проблемы

### 2.2 Мобильная версия

- `/search`: сетка `260px 1fr` без медиа-запроса, на телефоне сайдбар и результаты стоят рядом с горизонтальным скроллом (`app/search/page.jsx:158`).
- Навигация в шапке на ширине <600px скрывается полностью, бургер-меню нет (`app/globals.css`, `.ak-nav-desktop`).
- У страницы ресторана (`/r/[id]`) нет футера.

### 2.3 SEO

- Нет `sitemap.xml`, `robots.txt`, canonical, Open Graph, favicon, JSON-LD (`Restaurant` / `LocalBusiness`).
- Нет ни одной обычной ссылки `<a href>` на страницы заведений: карточки на главной и в поиске открываются через `onClick` + `router.push`. Краулер с главной не дойдёт до 106 страниц заведений и сетей. Единственные настоящие ссылки — в блоке «Ähnliche Lokale».
- `<title>` и хиро говорят «in Wien», остальные тексты — «Österreich». Заведения есть в Graz, Linz, Salzburg, Innsbruck, Klagenfurt, Wels, Leonding, Wiener Neustadt, Vösendorf.
- Нет посадочных страниц по районам и кухням.
- `lang` на `<html>` меняется на клиенте, hreflang нет.
- Метаданные в `app/layout.jsx` минимальные (title + description).

### 2.4 Поиск и фильтры

- `SEARCH_EXTRA` в `data/search-data.js` ссылается на удалённые демо-id (`al-nour`, `pizza-medina` и т.д.). У реальных записей нет полей `cuisine`, `openNow`, `hours`, `services`, `dietary`, `distance`, `lastVerifiedDays`, `addedDaysAgo`.
- Из-за этого фильтры «Küche», «Jetzt geöffnet», «Service», «Diät», «Familie», «Bewertung» и сортировки «Entfernung», «Zuletzt verifiziert», «Neueste» не работают на реальных данных. Фильтр «Küche» скрывает вообще всё.
- Список кухонь `CUISINES` (Turkish, Lebanese, Pakistani, Indian, Afghan, Uzbek…) не соответствует реальным категориям заведений.

### 2.5 Карта и фото

- Карта Вены нарисована руками: SVG с районами-многоугольниками, позиции заведений заданы как `x`/`y` в процентах, географических координат нет. При этом стоит подпись «© Akiwi · OpenStreetMap contributors», хотя OSM не используется. Кнопки зума ничего не делают (`components/Map.jsx`).
- Мини-карта на странице ресторана декоративная (`components/detail-sections.jsx`, `MiniMap`).
- Фотографий нет ни у одного заведения, везде градиенты (`gallery` в `venues.js` — это цвета, не картинки).

### 2.6 Код и репозиторий

- **Мёртвый код, примерно половина репозитория:** папка `src/` (старое Babel-приложение, 20 файлов, отличается от `components/`), 9 HTML-прототипов в корне (`Akiwi Homepage.html` и др.), `tweaks-panel.jsx`, `index.html`, `colors_and_type.css`, `assets/` (дубль `public/assets`).
- Инструкция в шапке `data/venues.js` устарела: ссылается на `src/data.jsx`, папку `restaurants/[id]/` и поддомены `[id].akiwi.at`.
- Состояние языка скопировано в 4 страницы (`app/page.jsx`, `app/search/page.jsx`, `app/r/[id]/Detail.jsx`, `app/chain/[id]/ChainDetail.jsx`) с двумя разными ключами localStorage: `akiwi.lang` и `akiwi_lang`. Язык сбрасывается при переходе на `/search`.
- Синхронный доступ к `params` в `app/r/[id]/page.jsx` и `app/chain/[id]/page.jsx` устарел в Next 15 и сломается в Next 16 (нужен `await params`).
- Все стили inline в JSX, Tailwind не используется. Это не баг, но мешает поддержке.
- Шрифты: два TTF по ~700 KB (`public/fonts/`). Лучше `next/font` или woff2-сабсет.
- HTML главной 210 KB, в основном из-за бегущей строки (68 элементов × 2 полосы).
- Нет ESLint-конфига, тестов, README, CI.
- Web Analytics на Vercel не включена.

### 2.7 Мёртвые элементы интерфейса

- Форма рассылки в футере (`onSubmit` → `preventDefault`).
- Кнопка «Bewertung schreiben».
- Кнопка «Ungenauigkeit melden».
- Кнопки «+ / −» на карте.
- Кнопка «Eintrag beanspruchen» → 404.

## 3. Принятые решения (обсуждение 2026-09-18)

1. **Юридические страницы (Impressum, Datenschutz):** пока не добавляем. Владелец добавит тексты позже. До этого момента ссылки на несуществующие страницы убираем из шапки и футера, чтобы не было 404. Место в навигации остаётся, вернём ссылки, когда появятся страницы.
2. **База данных / Supabase:** не сейчас. Все данные вносит владелец лично в JS-файлы в репозитории. Админку для владельцев ресторанов пишем только когда появится спрос от них.
3. **Фейковые рестораны и счётчик «142»:** убираем. Это остатки прототипа.
4. **Статусы верификации:** значения оставляем как есть (verified / self / unknown, как записано сейчас). Реальных проверок на месте пока не было, но сайт не должен выглядеть «всё непроверено».
   - Статус должен храниться **в одном месте** (поле в записи заведения в `venues.js`) и легко меняться правкой одной строки.
   - Статус сети вычисляется из статусов филиалов, а не задаётся отдельно.
   - Главная и поиск не дублируют данные, а строятся из `venues.js` + `chains.js`.
5. **Текст под бейджем «Verifiziert»:** вариант A. Бейдж остаётся зелёным, формулировка меняется на честную: «Halal-Status laut Betreiber bzw. Website des Lokals bestätigt.» (EN: «Halal status confirmed by the venue's owner or website.»). Когда начнутся реальные проверки на месте, добавим отдельный, более высокий уровень «Vor Ort geprüft».

## 4. Открытые вопросы

- Цель проекта на ближайшие месяцы: органический трафик из Google, продажа платных профилей владельцам, или и то и другое? Влияет на приоритет SEO-этапа и страницы `/for-owners`.
- Карта: переходить ли на реальную (Leaflet + OpenStreetMap, бесплатно)? Потребуется геокодировать 87 адресов.
- Фото: откуда брать снимки заведений (свои, от владельцев, лицензированные)?
- Тексты Impressum / Datenschutz: когда будут готовы.

## 5. Предлагаемый порядок работ

Каждый этап — отдельная задача со своим планом. Порядок по убыванию срочности.

**Этап 1. Честность данных и битые ссылки (1–2 дня)**
- Удалить фейковые рестораны и `SEARCH_EXTRA` из `search-data.js`.
- Счётчик в хиро считать из реальных данных.
- Убрать выдуманную гистограмму отзывов; при нулевых отзывах показывать «Noch keine Bewertungen».
- Убрать общее описание из `Detail.jsx`; показывать `tagline` или поле описания из записи заведения.
- Сменить текст под «Verifiziert» (решение 5).
- Починить переход из поиска на страницы сетей.
- Убрать из шапки/футера ссылки на несуществующие страницы (решение 1).
- Не показывать рейтинг «4.0 (0)» как настоящий: при `reviews: 0` рейтинг скрывать.

**Этап 2. Единый источник данных**
- Главная и поиск строятся из `venues.js` + `chains.js`, файл `data.js` со списком карточек убирается или генерируется.
- Статус сети вычисляется из филиалов (решение 4).
- Обновить инструкцию «как добавить заведение» в шапке `venues.js`.

**Этап 3. SEO-фундамент**
- `sitemap.xml`, `robots.txt`, canonical, Open Graph, favicon.
- Карточки как настоящие ссылки `<a href>` / `<Link>`.
- JSON-LD `Restaurant` на страницах заведений.
- Единая формулировка «Österreich» в title и хиро; метаданные per-page.
- Позже: посадочные страницы по городам/районам и кухням.

**Этап 4. Мобильная версия и поиск**
- Адаптивная сетка `/search`, бургер-меню, футер на странице ресторана.
- Фильтры поиска привести к реальным полям данных (категории, статус, район/город, цена); нерабочие фильтры убрать.

**Этап 5. Чистка репозитория и код**
- Удалить `src/`, HTML-прототипы, `tweaks-panel.jsx`, `index.html`, `colors_and_type.css`, `assets/`.
- Один общий хук/контекст для языка с одним ключом localStorage.
- `await params` в динамических страницах.
- ESLint, README.
- Шрифты через `next/font`.
- Включить Vercel Web Analytics.

**Этап 6. Карта и фото (после ответов на открытые вопросы)**
- Реальная карта на Leaflet + OSM, координаты для всех заведений.
- Фотографии заведений.

**Позже, по спросу:** формы для владельцев, отзывы, админка, база данных.
